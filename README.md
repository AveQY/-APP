## 项目简介

一个基于 Lua / AndroLua 的 Android 模板化 APP 生成工具，应用名称为 **一键生成APP**。通过预置模板、解压资源、修改配置和页面跳转的方式，帮助用户不用写任何代码就能实现一键快速生成不同类型的 Android 应用。

**视频介绍：** [纯纯的小白也会制作软件APP了！](https://www.bilibili.com/video/BV17U4y1v7Fz/?share_source=copy_web&vd_source=0f5f22cb3bf4455cc820a63ea7bc2732)
**说明：** 本项目已不在维护，如果你有想法欢迎二创修改！

“模板工程生成器”：

1. 用户选择模板
2. 程序把模板资源解压到本地工程目录
3. 将应用名、版本号、包名等参数写入模板工程
4. 跳转到对应页面继续编辑或打包

## 项目特性

### 1. 一键生成多种 APP 模板

项目内置多种应用模板，可根据不同场景快速初始化工程。

已确认的模板类型包括：

- 图片模板
- 视频模板
- 音乐模板
- 密码模板
- 网页模板
- 游戏模板
- 工具模板
- 自定义模板
- 编辑模板

其中部分模板还包含二级子模板，例如：

- 密码模板：图片 / 视频 / 网页 / 音乐
- 游戏模板：五子棋 / 井字棋 / 别踩白块儿
- 工具模板：网抑云

### 2. 模板资源自动解压与工程初始化

点击“开始制作”后，程序会自动：

- 清理旧工程目录
- 创建新的工程目录
- 解压基础模板资源
- 按模板类型叠加子模板资源
- 复制默认图标
- 记录当前模板状态

这使得整个项目具备明显的“工程脚手架”属性。

### 3. 支持模板参数注入

项目提供公共生成逻辑，会直接修改模板工程中的 `init.lua`，替换以下关键字段：

- `appname`
- `appver`
- `packagename`

也就是说，它不仅能初始化模板，还能把用户填写的应用信息写入生成项目。

### 4. 支持模板状态持久化

项目会把当前模板和部分配置保存在本地目录中，方便后续继续编辑或恢复上次状态。

### 5. 包含布局助手、工具页与扩展模块

从仓库文件命名和 README 说明来看，项目除了模板生成能力，还包含：

- 布局备份管理
- 自定义模板布局助手
- AndLua 布局助手
- 作者自制软件入口
- 工具模块

这使它不仅是一个模板生成器，也更像一个围绕 AndroLua 生态打造的“开发辅助工具集”。

## 技术栈

- **语言**：Lua、HTML
- **运行平台**：Android
- **运行环境**：AndroLua / Lua + Android API
- **界面方式**：Lua Table 描述 Android 布局
- **资源处理**：Zip 解压、文件复制、目录初始化
- **网络能力**：`Http.get`、`Http.download`
- **数据处理**：字符串替换、JSON 解析、XML 转 Table
- **原生扩展**：`.dex` 文件（如 `mao.dex`、`sign.dex`）

## 核心文件说明

### `code/main.lua`

项目主入口页面，也是首页控制中心。

主要职责：

- 展示当前模板
- 提供“开始制作”“选择模板”“我的软件”“关于软件”等入口
- 根据模板类型决定解压哪些资源
- 将工程初始化到本地路径
- 跳转到对应后续页面继续编辑

它本质上是整个项目的**模板分发中心**。

### `code/init.lua`

应用初始化配置文件，定义：

- 应用名称
- 包名
- 版本号
- SDK
- 调试状态
- Android 权限列表

### `code/function.lua`

项目的公共函数库，负责：

- UI 工具函数（边框、圆角、动画、提示、弹窗）
- 初始化目录结构
- 公告与一言拉取
- 文件选择器调用
- 文件下载
- 应用信息写回模板工程

其中最关键的能力之一，是把用户填写的应用名称、版本号和包名写回模板的 `init.lua`。

### `code/layout.lua`

定义了项目中的基础布局模板，包含：

- `main`：主界面根容器
- `dlg`：输入型编辑对话框
- `ck`：单选确认界面

项目大量依靠 Lua Table 动态构建 Android UI。

### `code/main2.lua ~ main11.lua`

这些文件很可能分别对应不同的模板编辑页、生成页、扩展页或管理页。结合 `main.lua` 已确认的跳转关系，可以确定其中至少包含：

- 普通模板后续页
- 密码模板后续页
- 自定义模板页
- 我的软件页

### `code/libs/`

这个目录很可能是模板资源包的核心来源。源码中已确认会从这里解压不同模板，例如：

- `MyApp`
- `video`
- `Music template`
- `music`
- `web`
- `password`
- `customize`
- `game/*`

这也是项目能够“一键生成”的关键资源来源。

## 主界面功能

根据 `main.lua`，首页已确认包含以下核心交互：

### 1. 开始制作

读取当前模板，然后：

- 清空旧工程目录
- 解压基础模板
- 解压对应子模板
- 复制图标
- 记录状态
- 跳转到下一页面

### 2. 选择模板

通过单选对话框选择一级模板；如有需要，再进入二级模板选择。

### 3. 我的软件

跳转到 `main11`，用于查看或管理已生成的软件。

### 4. 关于软件

调用关于页逻辑，展示版本或项目说明。

## 模板生成流程

这个项目最核心的使用流程可以概括为：

```text
打开应用 -> 选择模板 -> 点击开始制作
-> 删除旧工程目录
-> 解压基础模板工程
-> 按模板类型叠加子模板资源
-> 复制默认图标
-> 写入当前模板状态
-> 跳转到后续编辑页
-> 填写应用名/版本/包名并继续生成
```

其中，参数写入阶段会修改模板工程中的 `init.lua`。

## 本地目录与状态文件


## 如何阅读这个项目

如果你第一次接手该项目，推荐按下面顺序阅读：

1. `code/init.lua`：先看运行环境与权限
2. `code/main.lua`：理解模板选择与生成主流程
3. `code/function.lua`：掌握公共函数和参数写回机制
4. `code/layout.lua`：看基础 UI 模型
5. `code/main2.lua ~ main11.lua`：逐步确认各模板页职责
6. `code/libs/`：查看不同模板资源的真实内容
